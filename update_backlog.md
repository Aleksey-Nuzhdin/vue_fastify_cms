# Backlog улучшений VFC

Пополняется по результатам фаз аудита (план — `update_plan.md`, карта — `update_1_map.md`).
Каждый пункт → отдельная задача → отдельный коммит.

## Актуальные задачи

1. **Sharp-ресайзер: лимит параллельных воркеров.**
   Уточнение по итогам фазы 1: дедупликация одинаковых задач УЖЕ есть —
   `resizeInProgress` map (`fsStorage.service.ts:60,82-83`). Осталась проблема:
   каждый ресайз спавнит новый worker thread (`fsStorage.service.ts:93`) без
   ограничения их числа — неавторизованные запросы к РАЗНЫМ картинкам/размерам
   порождают неограниченно много параллельных воркеров. Нужен пул/очередь
   (лимит 1-2 воркера) и/или ужесточение rate-limit для `/upload/images/*`.

2. **Multipart: отдельный лимит на аватар.**
   `app.ts:34-37` — глобальный лимит 100MB действует и на
   `/api/profile/upload/avatar`, доступный любому залогиненному при открытой
   регистрации. Задать маленький лимит на этом роуте (например 5MB) и
   проверить, пережимается ли аватар после загрузки.

## Бэклог

- **Helmet: включить CSP.** `app.ts:30-32` — `contentSecurityPolicy: false`.
  Пользовательский HTML (Quill) сейчас защищён только DOMPurify на клиенте;
  CSP — вторая линия обороны от XSS. Включить с исключениями для Swagger UI
  и инлайн-скриптов SPA, если понадобятся.

- Хрупкое место (не безопасность): `upload.controller.ts:16` —
  `.replace('upload', '')` заменяет первое вхождение подстроки где угодно
  в пути; файл/папка со словом «upload» в имени станет недоступен.
